# /バッティング確認 — 矛盾・重複候補の検出

## 目的
本番反映対象の行（清書完了=TRUE かつ ステータス=有効）の間で、
矛盾・重複の候補をID付きで検出し、人の判断材料を提示する。
**検出まで。DBの修正はこのコマンドでは行わない**（修正は人が判断し、必要なら別途依頼される）。

## 判定基準（設計書8章）

- **矛盾候補**: 同一の大ジャンル＋類似テーマの行で、数値・手順・呼称が食い違うもの。
  例: 同じドリンクの分量が行によって違う / 同じ作業の手順・タイミングが食い違う /
  同じ席・備品の呼び方が揺れていて誤解を生みうる
- **重複候補**: 表現は違うが実質同じルールを述べている行の組
- 大ジャンルをまたぐ矛盾もありうる（例: チェックリストと個別ルールの食い違い）ので、
  CL_系シートの項目とメインシートの行の突き合わせも行う。

## 手順

1. ①DBから 清書完了=TRUE かつ 有効 の全行と、CL_系4シートの全項目を読む。

2. テーマの近い行同士を突き合わせ、矛盾候補・重複候補を抽出する。
   機械的な完全一致ではなく、文脈で「現場が混乱しうるか」を基準に判断する。

3. 結果を以下の形式で報告する:

   ```
   ■ 矛盾候補
   1. [ID 12] ディナー ドリンク分量 vs [ID 13] 日本酒KEG 価格・分量
      → KEGグラス1杯の分量が 80cc / 80〜90cc で食い違い
      推奨: どちらかに統一（判断材料: ...）

   ■ 重複候補
   1. [ID 8] キャンセル料 と [ID 48] キャンセル発生時のキッチン共有
      → キッチン共有の記述が両方にある。統合 or 片方から削除を検討
   ```

4. 候補0件なら「バッティングは検出されませんでした（対象X行）」と報告。

## 注意
- 「絶対に矛盾」と断定しない。あくまで候補として提示し、判断は人に委ねる。
- 誤検知を恐れて絞りすぎない。グレーは「参考」として末尾に載せてよい。
