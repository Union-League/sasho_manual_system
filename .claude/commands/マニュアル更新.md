# /マニュアル更新 — ①DBから②③PDFを再生成し共有フォルダへ配置

## 目的
①DBの本番反映対象行から、②完全版・③新人向けのPDFをHTML経由で生成し、
共有用フォルダの固定PDFを差し替える。差し替え前に旧版を履歴フォルダへ退避する。

## 成果物

| 成果物 | ファイル名 | 置き場所 |
|---|---|---|
| ② | Sasho｜マニュアル｜完全版.pdf | 共有用フォルダ（固定ファイルIDを差し替え） |
| ③ | Sasho｜マニュアル｜新人向け.pdf | 同上 |
| 旧版 | Sasho｜マニュアル｜完全版_YYYY-MM-DD.pdf 等 | 履歴フォルダ |

Googleドキュメントは使わない。共有用フォルダ・履歴フォルダのIDはCLAUDE.md参照。

## 手順

### 0. 準備
- 実行者の名前を確認する。
- ①DBから 清書完了=TRUE かつ ステータス=有効 の全行と、CL_系シート全部を読む
  （シート数は増える。CL_で始まるシートを動的に列挙し、数を決め打ちしない）。
- 画像列にURLがある行は、Drive APIで画像をローカルに一時ダウンロードしておく
  （HTML内でローカルパス参照するため）。

**生成前チェック（不整合があれば生成を続けつつ必ず報告する）**:
- **チェックリスト行の項目数**: 「内容」に「（N項目）」と書かれている場合、
  参照先CL_シートの実項目数と一致するか照合する。CL_シートは随時書き足される運用のため、
  DB側のサマリ文が古くなりやすい。不一致は報告し、DB修正→再生成を促す。
- **参照先シートの存在・非空**: 内容種別=チェックリストなのに参照先シートが無い／空の行。
- **「シート参照」文言の混入**: 「内容」セルに「詳細は専用シート参照」等が残っていないか。
  PDFには全項目を展開するため、この文言は読者にとって無意味・紛らわしい。
- **新人向けフラグ=TRUE が0件**: ③が中身の無いPDFになるため、③の生成前に確認を取る。
- **未知の大ジャンル**: 13ジャンルのどれにも一致しない値。章から漏れるため報告。

### 0.5. 検索キーワードの生成（このコマンドが唯一DBに書き込む処理）

対象 = 清書完了=TRUE かつ 有効 かつ **検索キーワード列が空欄** の行。人のレビューは取らず、
生成したらそのままQ列に書き込む（PDF生成の前に済ませる）。

各行に、**その項目を探している人が打ちそうな語**を半角スペース区切りで15〜25語入れる:

| 入れるもの | 例 |
|---|---|
| 表記ゆれ | iPad／アイパッド／アイパット、ごまだれ／ごまダレ／胡麻だれ、割下／割り下 |
| ひらがな読み | わりした、たいてん、じゅうでん（漢字変換せず打つ人向け） |
| 別名・言い換え | ダスター＝ふきん＝雑巾＝布、インカム＝無線＝無線機 |
| **症状ベースの聞き方** | 「席が消えない」「空いてるのに入らない」「動かない」「来なかった」 |
| 数値・固有名詞 | 3000、8%、Usen、TableCheck |
| 疑問形 | いくら、何円、どこ、どれ使う、何をすれば |

- **症状ベースを必ず入れる**。これが無いと「空いてるのに予約が入らない」のような
  症状からの逆引きが不可能になる（ID135はこれで引ける）。
- **チェックリスト行**は、CL_シート側の項目に出るが独立行が無い語も親行に足す
  （例: ID1「朝の準備」に iPad／ハンディ／ガラスポット）。CL_シート側に列は増やさない。
- **接客の流れのような全体を覆う行に語を詰め込みすぎない**。何にでもヒットして
  検索精度が落ちる。全体像を指す語に絞り、個別の語は各行に任せる。
- 既に値がある行は**上書きしない**。内容やタイトルを変えた行は、Q列を空にすれば次回再生成される。

### 1. HTML生成（②③それぞれ）

構成（共通）:
- 表紙: タイトル（②「Sasho マニュアル 完全版」/ ③「Sasho マニュアル」）、生成日
- 注意書き: 「このPDFはYYYY年MM月DD日にマニュアルDBから自動生成されました。
  修正・追加の要望は経営陣へ。」
- 目次: 章（ジャンル）へのリンク（章名＋項目数）
  ※ページ番号は入れない。Chromeヘッドレス印刷はCSSの `target-counter` に未対応で、
    目次のページ番号を自動計算できない。実現するにはPaged.js等の外部ライブラリが必要。
    アンカーリンクはPDF内で機能するため、リンクで代替する
- 本文: 13ジャンル固定順（CLAUDE.md記載の順）。該当0件のジャンルは章ごと省略。
  ジャンル内の並び順のみClaudeが読みやすさで判断（時系列のある作業は時系列順など）。
- 内容の**意味を変えない**。数値・固有名詞・手順は一字一句DBに忠実に。文体変換のみ行う。

②完全版:
- 対象: 清書完了=TRUE かつ 有効 の全行
- 各項目見出しにID併記: `[12] ディナー ドリンク分量`
- チェックリスト行はCL_シートの全項目を本文中に番号付きリストで展開（シートの並び順のまま）
  ※スタッフが読むのはPDFでありDBではないため、PDFに「CL_○○シート参照」とは書かない。
    シート名参照はあくまで①DB側でリストを分離管理するための仕組み
- **備考列は②③どちらにも出さない**（下記「備考列の扱い」参照）
- 文体: 簡潔な常体ベース

③新人向け:
- 対象: 上記のうち 新人向けフラグ=TRUE のみ
- ID・備考は載せない
- チェックリスト行はCL_シートの全項目を本文中に番号付きリストで展開（②と同じ）
- 文体: です・ます調。「なぜそうするか」を一言添える
  （DBの「内容」から読み取れる範囲で。推測で理由を創作しない）

**備考列・検索キーワード列の扱い（重要）**:
どちらも内部データであり、②③どちらにも出力しない。検索キーワードはHTML版の検索専用で、
PDFに出しても読者には無意味なノイズになる。

備考は**経営陣のための内部メモ**であり、②③どちらにも出力しない。実際の中身は
「ID◯◯へ統合」「原本と照合推奨」「OCR由来」「取込時に欠落…復元」「専用シートで管理」
「経験者向けなので新人向け=FALSE」といった編集履歴・データ品質メモ・判断根拠であり、
スタッフには無意味なうえ、料金表に「OCR由来のため照合推奨」と出れば記載の信頼性を損なう。

- 読者に読ませたい補足は、備考ではなく**「内容」列に書く**（1列1用途を保つ）。
- 備考にある他行への参照（例「詳細はID88参照」）はそのまま出さない。
  PDF上は節・見出しの名前で参照する（例「5-3 インカム運用」参照）か、
  関連項目を同じ節にまとめて配置することで解決する。読者はIDを知らない。

デザイン:
- A4縦・印刷前提。日本語フォント指定必須（下記PDF化の項参照）
- 落ち着いた配色（墨色基調＋アクセント1色程度）。高級和牛料理店にふさわしい静かなトーン
- 見出しは明朝、本文はゴシック（料亭らしい品位を出すため）
- 画像はサイズ・配置を整えて本文中に埋め込む

**編集方針（重要）— DBはあくまでinput。並べ替えて転記するだけにしない**

DBの行をID順に並べただけの出力は不可。読み物として完成した誌面に仕上げる。
事実・数値・固有名詞・手順・セリフはDBのとおりで変更しないが、それ以外は自由に編集してよい。

- **章内を節に分ける**: 40項目がフラットに並ぶと読み通せない。業務の流れと意味のまとまりで
  節（5-1, 5-2…）に再編し、ID順ではなく理解しやすい順に並べる。
- **章の冒頭にリード文と節の一覧を置く**: 全体像から入れるようにする。
- **同趣旨の複数行は1つの表・1つの節にまとめる**: 例「症状→対処」の表に統合。
- 追記してよいのは見出し・節名・リード文・フェーズ名といった**導線の言葉のみ**。
  業務内容の断定・理由づけを創作しない。

**表現部品の使い分け**（内容の型を見て選ぶ）

| DBの内容がこうなっていたら | この形にする |
|---|---|
| 時系列の手順・一連の流れ | フェーズで区切った縦タイムライン（番号付きノード） |
| 手順＋その理由 | 「手順／操作／理由」の3列表 |
| 複数の並列ルール（〇〇の4ルール等） | 番号付きカード |
| NG例／OK例 | 赤（NG）と緑（OK）の左右対比ボックス |
| セリフ・トーク例 | 話者ラベル付きの会話形式 |
| 定型の伝達フォーマット | 記入欄（下線）付きの枠 |
| 対象ごとに条件が違う（A社/B社、男性/女性、昼/夜） | 比較表（マトリクス） |
| 禁止事項・事故につながるもの | 琥珀色の警告ボックスで強調 |
| 変換前後・対応関係（電話番号、旧料金→新料金） | 2列の対応表 |
| 色を指定するルール（青のダスター等） | 実際の色見本（●）を添える |
| 番号付きの操作手順 | 丸番号のステップリスト |
| 内容中の「【背景】」「補足」 | 本文と区別した薄いグレーの補足ボックス |

- 密度の目安: 137項目全体で60〜80ページ規模。②完全版は引く資料なので密度は高くてよい。
- IDは読み物の邪魔にならないよう、見出しの右端に小さく添える（②のみ。③は載せない）。

### 2. PDF化

Chrome/Chromiumのヘッドレス印刷を使う（Mac/Windows両対応・追加インストール不要）:

```
# Mac
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --print-to-pdf=output.pdf --no-pdf-header-footer input.html

# Windows (PowerShell)
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --headless --disable-gpu --print-to-pdf=output.pdf --no-pdf-header-footer input.html
```

- ページ設定・余白はHTML側の `@page` CSSで制御する
- 生成後、PDFが開けること・文字化けがないことを確認してから次へ進む
  （日本語が豆腐（□）になる場合はfont-family指定を見直す:
   Mac=Hiragino Sans / Windows=Yu Gothic / 両対応は "Hiragino Sans","Yu Gothic",sans-serif）

### 3. 旧版の退避

- 共有用フォルダの現行PDF（固定ID）をDrive API `files.copy` で履歴フォルダへコピー
- コピー名: `Sasho｜マニュアル｜完全版_YYYY-MM-DD.pdf` / `Sasho｜マニュアル｜新人向け_YYYY-MM-DD.pdf`
  （同日2回目以降は `_YYYY-MM-DD_HHMM.pdf`）
- **コピー成功を確認してから次へ進む**。失敗したら差し替えは行わず中断・報告。
- 初回（共有用フォルダにまだPDFが無い場合）は退避をスキップし、新規アップロードして
  そのファイルIDをCLAUDE.mdに記録するよう報告する。

### 4. 差し替え

- Drive API `files.update`（media upload）で、固定IDのPDFの**中身だけ**を差し替える
- ファイルIDが変わらないため、スタッフに配布済みのリンクはそのまま生きる
- ②→③の順に処理。②で失敗したら③に進まず報告。

### 5. 結果報告

- 「②を更新しました（X項目）。③を更新しました（Y項目）。
   旧版は履歴フォルダに退避済み: <コピー名2つ>」
- 共有用フォルダ内の②③PDFのリンクを併記する。

## 注意
- このコマンドが①DBに書き込むのは**検索キーワード列（Q）だけ**（手順0.5）。
  それ以外の列・行は一切書き換えない。内容の修正が必要な不整合を見つけた場合は、
  自分で直さず報告し、/清書チェック で人の判断を経て直す。
- Googleドキュメントは生成しない・使わない。
- 清書完了=FALSEの行がある場合、生成は行うが「未清書がN件あります（反映されていません）」と添える。
- HTMLソースは `output/` 配下に日付付きで残す（デザイン調整の再利用・差分確認用）。
