# /清書チェック — 未清書行の清書ドラフト提案

## 目的
清書完了=FALSE の行を対象に、読める日本語に整えた下書きを提案し、
人の確認を経てDBへ反映する。**勝手に清書完了=TRUEにはしない**（TRUEにするのは人の判断）。

## 手順

1. 実行者の名前を確認する。

2. ①DBから 清書完了=FALSE の行を全件読む。0件ならその旨を報告して終了。

3. 各行について以下のドラフトを作成する:
   - **内容**: 素起こし文を、既存の清書済み行（清書完了=TRUEの行）と同じトーンの
     簡潔な日本語に整える。事実・数値・固有名詞は一切変えない。
     原文に無い情報を推測で足さない。判断がつかない箇所は「【要確認】」を付けて残す。
   - **タイトル**: 一行要約として適切か見直す。
   - **大ジャンル**: 仮判定の妥当性を確認し、変更提案があれば理由付きで示す。
   - **内容種別**: 手順の羅列で増減しやすいものはチェックリスト化
     （別シート新設 or 既存CL_シートへの追記）を提案。
   - **新人向けフラグ**: 提案する。判断基準:
     - TRUE寄り: 日常オペレーション・接客・清掃・安全に関わる全スタッフ向けルール
     - FALSE寄り: 発注業務・レジの高度な操作・時期限定ルール・経営判断事項
   - **粒度**: 1行に複数の独立ルールが混在していれば分割案を、
     過剰に細切れなら統合案を提示（「中間」方針）。
   - **図表化**（下記「図表化の判断」を必ず実施）: ベタ文のままでは視認性が悪い内容を
     表・配置図・対比などに変換する。単純な転記で済ませてはいけない。

## 図表化の判断（この工程の必須作業）

内容の型を見て、下表に当てはまるものは**必ず**図表にする。当てはまらないものはテキストのまま。

| 内容がこうなっていたら | 表示形式 | 例 |
|---|---|---|
| 2軸のマトリクス（A×B → 値） | **表** | ディナーコース料金（コース×牛の種類） |
| 項目ごとに属性が並ぶ | **表** | ドリンク分量（銘柄／分量／グラス） |
| 物の位置・棚・座席の配置 | **配置図** | くつ箱（左右×段） |
| 対象で基準が違う | **対比** | 頭髪・服装（男性／女性） |
| 色で用途を指定 | **色見本** | ダスター（実際の色を出す） |
| 時刻・季節・順序がある | **タイムライン** | 1日の流れ、ランチョンマットの季節順 |
| 変換前→変換後、旧→新 | **対応表** | 国際電話の010付与、旧料金→新料金 |
| 番号付きの操作手順 | **手順** | ビールサーバー洗浄、iPad復旧 |

**書き込み先**: ①DBと同じファイルの **「図表」シート**（マニュアルDBに列は作らない）

| 列 | 内容 |
|---|---|
| ID | マニュアルDBのID |
| 表示形式 | 上表のいずれか |
| セル1〜6 | 中身。列数が足りる範囲で使い、余りは空欄 |

表示形式ごとの列の意味:
- **表 / 対応表**: 各IDの**1行目がヘッダー行**、以降がデータ行
- **配置図**: セル1=グループ（左側/右側）/ セル2=位置（上段/中段）/ セル3=中身
- **対比**: セル1=対象（男性スタッフ等）/ セル2=項目（1項目1行）
- **色見本**: セル1=色名 / セル2=カラーコード（`#3f6fb5`）/ セル3=用途
- **タイムライン**: セル1=時刻・見出し / セル2=内容 / セル3=補足
- **手順**: セル1=手順の内容（並び順のまま番号が振られる）

**あわせて行うこと**:
- 「内容」列を**要約1行に差し替える**（図表と同じ情報を二重に持たない）。
  ただし図表に入らない補足（例外・注意・理由）は要約側に残す。
- 検索キーワード列（Q）を空にする → 次回の /マニュアル更新 が図表を含めて作り直す。

**レビューの取り方**:
図表は**シート上で直接確認していただく**。チャットで1件ずつ承認を取らない
（20件超を会話で回すのは非効率）。書き込んだ後に「図表シートのID◯◯〜を確認してください」
と伝え、行列の切り方が違えばシートで直してもらう。
ただし**行列の切り方が一意に決まらない場合は案を2つ出して選んでもらう**。
情報が足りず図にできない場合（写真・実測が必要等）は図表を作らず【要確認】として報告する。

4. 提案を行ごとに「ID / 現状 → 提案 / 論点」の形式で提示し、人の承認を待つ。

5. 承認された行のみDBへ反映する:
   - 内容・タイトル・大ジャンル・内容種別・新人向けフラグを更新
   - 分割の場合: 新IDで行を追加し、元行は内容を分割後の1件に縮めるか、
     ステータス=廃止＋備考に「ID X, Y へ分割」と記録（人に選ばせる）
   - 最終更新者=実行者名、最終更新日=今日
   - **内容またはタイトルを変更した行は、検索キーワード列（Q）を空にする**。
     次回の /マニュアル更新 が新しい本文に合わせて作り直す（古いキーワードが残ると
     HTML版の検索がずれる）。キーワードを自分で書く必要はない。
   - **清書完了は人が「TRUEにして」と明示した場合のみTRUEにする**

## 注意
- 一度に大量の行がある場合は5〜10件ずつ提示し、レビュー疲れを防ぐ。
- 【要確認】が残る行はTRUE化を推奨しない旨を明示する。
